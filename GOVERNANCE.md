# Governance

## Claim governance

- Every material security or product claim should have a stable identifier.
- Claims may not inherit evidence from a narrower chain, venue or capability.
- Historical evidence remains distinguishable from current status.
- Independent-assessment language requires a named external issuer and a publishable reference.
- Token-economic rights require separate legal, governance and implementation approval.

## Repository governance target

The public repository should use:

- protected `main`;
- pull-request-only changes for trust/security/claims files;
- required public-evidence verification checks;
- CODEOWNERS review;
- secret scanning;
- release-specific evidence rather than hand-edited blanket status prose.

Repository-management settings are GitHub configuration, not evidence; their status should be verified directly in GitHub.
